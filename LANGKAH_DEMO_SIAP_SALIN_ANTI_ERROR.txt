BAGIAN 3: ANDHI YUDHA PERMANA (1224017) - KASIR POS (SHARED DB & RFC 9457)
WAKTU: MENIT 02:00 - 03:00
================================================================================

[Langkah 3.1] Cek Stok Sembako Sebelum Transaksi (1 Baris Langsung dari Bash):
docker exec warung_ibu_beti-mysql-1 mysql -u sail -ppassword warung_beti -e "SELECT sku, nama_barang, stok, harga_jual FROM barang;"

[Langkah 3.2] Transaksi Kasir POS Tunai (Beli 2 Beras + 1 Minyak, Uang Rp200.000):
curl -X POST http://localhost:8090/api/v1/kasir/transaksi -H "Content-Type: application/json" -d '{"kasir_nama":"Mbak Beti","metode_bayar":"tunai","uang_diterima":200000,"items":[{"sku":"BRS-PREM-5KG","qty":2},{"sku":"MYK-GRG-2L","qty":1}]}'

[Langkah 3.3] Buktikan Stok Beras Terpotong Instan di MySQL (Row-Lock ACID):
docker exec warung_ibu_beti-mysql-1 mysql -u sail -ppassword warung_beti -e "SELECT sku, nama_barang, stok FROM barang WHERE sku='BRS-PREM-5KG';"

[Langkah 3.4] Transaksi Kasir POS Digital QRIS (Beli 2 Minyak Goreng):
curl -X POST http://localhost:8090/api/v1/kasir/transaksi -H "Content-Type: application/json" -d '{"kasir_nama":"Mbak Beti","metode_bayar":"qris","items":[{"sku":"MYK-GRG-2L","qty":2}]}'

[Langkah 3.5] Pembuktian Proteksi Stok Habis (Beli 999 Beras -> Error RFC 9457 HTTP 422):
curl -X POST http://localhost:8090/api/v1/kasir/transaksi -H "Content-Type: application/json" -d '{"kasir_nama":"Mbak Beti","metode_bayar":"tunai","uang_diterima":100000000,"items":[{"sku":"BRS-PREM-5KG","qty":999}]}'

--- Skrip Narasi Andhi ---
"Terima kasih Aldi. Bapak/Ibu Dosen, saya mendemonstrasikan modul Kasir POS toko fisik yang mengadopsi Shared Database dengan Pessimistic Row Locking SELECT FOR UPDATE. Ketika Mbak Beti memproses pembelian tunai Rp200.000, struk 201 Created keluar seketika dengan kembalian Rp12.000, dan stok beras langsung terpotong detik itu juga di MySQL. Saat dicoba transaksi 999 karung beras melebihi stok, sistem secara otomatis melakukan rollback transaksi dan merespons dengan galat standar RFC 9457 Problem Details HTTP 422 Stok Tidak Mencukupi. Selanjutnya, ketua kelompok kami, Jacky Firmansah, akan mendemonstrasikan jalur asinkron Bot WhatsApp, RabbitMQ, dan pengujian otomatis."

[Langkah 4.1] Kirim Pesanan Daring WhatsApp (Ibu Siti Beli 3 Beras -> Respons 202 Accepted):

[Langkah 4.2] Tunjukkan Event Tersimpan Aman di Tabel Outbox MySQL (Status: pending):
docker exec warung_ibu_beti-mysql-1 mysql -u sail -ppassword warung_beti -e "SELECT id, event_nama, status, created_at FROM outbox_kirim ORDER BY id DESC LIMIT 1;"

[Langkah 4.3] Jalankan Daemon Pengirim Outbox ke RabbitMQ:
./vendor/bin/sail artisan pengadaan:kirim-outbox

[Langkah 4.4] AKSI DI BROWSER RABBITMQ (http://localhost:15676):

- Tunjukkan isi payload JSON pesanan Ibu Siti ke dosen!

[Langkah 4.5] Jalankan Worker Konsumen WhatsApp (Stok Dipotong & Kirim basic_ack):
./vendor/bin/sail artisan wa:proses-pesanan --timeout=3
*Refresh browser RabbitMQ: Kolom Ready kembali menjadi 0 (selesai diproses bersih)*

[Langkah 4.6] Jalankan Automated Test Suite PHPUnit (12 Tests, 38 Assertions 100% PASS):
./vendor/bin/sail artisan test

CHEATSHEET DARURAT KETIKA PRESENTASI (EMERGENCY FIX)
================================================================================
1. Jika port 8090 atau 15676 konflik / tabrakan:
docker stop $(docker ps -aq) && ./vendor/bin/sail up -d

2. Jika koneksi RabbitMQ connection refused saat awal:
./vendor/bin/sail exec rabbitmq rabbitmq-diagnostics ping

3. Jika data stok sembako berantakan karena bekas testing sebelumnya:
./vendor/bin/sail artisan migrate:fresh
